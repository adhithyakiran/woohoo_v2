7. The critical path, narrated

Take the compound utterance from Figure 1 — “it's too cold and send someone to fix the shower” — and follow it. This is the walkthrough to argue with; if this sequence is right, the rest of the document is detail.

 t=0ms      Guest speaks the wake phrase. Sensory THF fires on-device. Device plays a 60ms earcon
            immediately (perceived responsiveness is bought here, not later) and opens/reuses the WS.

 t=+40ms    Device begins streaming Opus frames. A 500ms pre-roll ring buffer is flushed first so the
            first syllable after the wake word is never clipped. AEC is already active.

 t=+40ms    ① DEVICE GATEWAY validates the client cert (already established on the persistent WS),
            looks up device_id → {tenant_id, property_id, room_id, capability_manifest_version,
            language, consent_state}. This resolution is CACHED — it must not cost a DB hit per turn.
            The resolved scope becomes an immutable "TurnContext" that follows the turn everywhere.

 t=+45ms    ② SESSION ORCHESTRATOR creates turn_id, starts the root trace span, loads session state
            from Redis (last 3 turns, pending clarification, last-referenced entity for anaphora).

 t=+50ms    ③ ASR ADAPTER opens a streaming recognition session, injecting phrase hints assembled from
            the property's own vocabulary: F&B menu items, amenity names, staff-facing terms, local
            landmarks, and the room's own device labels. This is worth several points of WER and is
            the single cheapest accuracy win available.

 ...        Guest finishes speaking. Device-side endpointer detects end-of-utterance (~380ms of
            trailing silence, adaptive) and sends an explicit end-of-turn control frame — the cloud
            does NOT wait for its own silence timer. This saves 200-400ms versus server-side VAD.

 t=+2,900ms Final transcript: "it's too cold and send someone to fix the shower, it's dripping".
 (~150ms      Confidence 0.91. PII redactor runs (no PII here). Transcript enters ④ THE ROUTER.
  after
  speech
  ended)

 t=+2,910ms ④ ROUTER: fast-lane matcher scores this. It is compound and contains a free-text
            maintenance description → no deterministic match → AGENTIC LANE. (Had the guest said
            "turn on the lights", the fast lane would have executed it by t=+3,000ms with no LLM call.)

 t=+2,915ms ⑤ AGENT RUNTIME assembles context:
              · system prompt (versioned artefact, cached)
              · TurnContext: property brand voice, room 412, language en-IN, time 23:14 local
              · capability manifest for THIS room, rendered as the available tool set
              · current room state snapshot (pre-fetched in parallel at t=+50ms — see §27)
              · last 3 turns of conversation
              · pending-ticket summary ("do not create a duplicate")
            Sends to Gemini 2.5 Flash with structured tool-calling enabled.

 t=+3,380ms Gemini returns TWO proposed tool calls in one turn:
              (a) climate.set_temperature { zone: "bedroom", target_c: 23.0 }
                  — chosen because state showed setpoint 19.5°C and the guest said "too cold"
              (b) service.create_request { category: "maintenance", subcategory: "plumbing",
                    description: "shower dripping", priority: "normal" }

 t=+3,385ms ⑥ POLICY DECISION POINT evaluates each independently:
              (a) climate.set_temperature → tier T1. Scope check: zone belongs to room 412 ✓.
                  Capability check: property has HVAC control ✓. Bounds check: 23.0 within the
                  property's permitted 18–26°C band ✓. Quiet hours: no restriction on climate ✓.
                  → ALLOW
              (b) service.create_request → tier T2. Duplicate check: no open plumbing ticket for
                  412 ✓. Rate limit: 3rd ticket this stay, cap is 10 ✓. It is 23:14 — property
                  policy says non-urgent maintenance after 22:00 is queued for 08:00 dispatch,
                  not suppressed. → ALLOW WITH ANNOTATION {dispatch_at: 08:00}
            Both verdicts are written to the audit record BEFORE execution.

 t=+3,390ms ⑧ MCP GATEWAY injects tenant/property/room scope server-side (the model's arguments are
            merged UNDER the injected scope — model-supplied scope fields are stripped, not trusted),
            then dispatches.

 t=+3,400ms (a) → ⑩ inncom-adapter → down the tunnel → Zone B Edge Gateway → INNCOM head-end →
                  fan-coil setpoint write. Adapter returns ack + verified new state.
            (b) → Service Request domain service → row in Aurora → event on ⑪ → staff app push +
                  ticket appears on the maintenance tablet queue for 08:00.

 t=+3,760ms Both results return to ⑤. The agent composes ONE reply, not two:
            "I've set it to 23 degrees, it'll warm up in a few minutes. I've also logged the dripping
             shower for maintenance — they'll come by after 8 in the morning so you're not disturbed
             tonight. Anything else?"

 t=+3,790ms ⑦ TTS ADAPTER begins streaming synthesis. First audio byte at ~+3,900ms.
            ⚠ BUT the guest has not been sitting in silence: at t=+3,400ms the orchestrator emitted a
            filled-pause acknowledgement ("Sure, one moment—") from the CACHED earcon/phrase set the
            instant the first tool call was authorised. Perceived latency is ~500ms, not ~3.9s.

 t=+3,900ms Audio streams to the device. Screen shows: 23°C · Maintenance request logged #4471.

 t=+4,400ms ⑫ AUDIT: the complete turn record is sealed and written — redacted transcript, TurnContext
            digest, model+prompt version, reasoning summary, both tool calls, both policy verdicts,
            both outcomes, latencies per span, cost. Raw audio was never written to disk at any point.
Three things to notice in that trace
  1. The acknowledgement is emitted before the answer exists. This is the single highest-leverage UX decision in the system and it costs nothing. See §20.4.
  2. Room state was pre-fetched at t=+50ms, in parallel with the guest still speaking. By the time the model needs it, it is already in the context. This removes an entire tool round-trip — roughly 400–600 ms — from the majority of turns. See §27.2.
  3. The policy verdicts were written before execution, not after. If the process dies mid-turn, the audit record still shows what was authorised. Log-after-the-fact loses exactly the records you need most.

9. Trust and network zones

The zone boundaries in Figure 1 are the security architecture in miniature. Each crossing has a defined authentication mechanism, a defined direction, and a defined failure behaviour.

X1Guest voice → DeviceNone (physical presence)InN/AAnyone in the room can act. Mitigation: no T3+ action is available without an explicit confirmation, and no action can affect another room (P2).

There is exactly one inbound path

X8 — the staff/admin API — is the only place where traffic originates outside Woohoo cloud and terminates inside it. Devices, edge gateways and vendor systems are all outbound-only. This is not stylistic: hotel IT will not open inbound firewall rules for a vendor, and if they would, you should not ask. Design accordingly from the first line of code, because retrofitting outbound-only onto a system that assumed inbound polling is a rewrite of the integration layer.
