Front MatterHow to read this document

This document is the complete target architecture for Woohoo V2 — the second generation of the in-room hospitality voice assistant, rebuilt around an agentic core. It is written to be reviewed and then executed against: every significant choice is stated as an explicit decision with the reasoning and the rejected alternatives beside it, so a reviewer can disagree with a specific line rather than the whole design.

Structure

Parts I–II
Context and the end-to-end picture. Read these even if you read nothing else — Part II contains the full system map from guest utterance to physical actuation and back.
Parts III–VIII
The build. Service decomposition, the voice pipeline, the agentic core, MCP, data, and the integration layer that talks to Honeywell / Interel / PMS.
Parts IX–XI
The things that make it a product rather than a demo: agentic safety, security, compliance and governance.
Parts XII–XV
Operating it: scale and unit economics, reliability, observability and evaluation, and the Docker → AWS deployment path.
Part XVI + Appendices
Roadmap, team shape, and the concrete contracts (tool schemas, event schemas, config schema) that the implementation starts from.

Conventions

  • Decision boxes are load-bearing. Changing one changes the build plan.
  • New marks components that do not exist today and must be built.
  • Risk tiers T0 T1 T2 T3 T4 are defined in Part IX and referenced throughout.
  • Prices and latency figures are indicative planning numbers current to early 2026. They are accurate enough to choose an architecture and wrong enough that you must re-quote before signing a contract. Every such figure is marked with a †.
Scope exclusions

Guest-facing and staff-facing UI is out of scope (owned by a separate workstream), but this document does specify the contracts the UI depends on — the staff task API, the notification event stream, and the device screen state protocol — because those are architecture, not presentation. Hardware/industrial design of the device enclosure is also out of scope; the device software architecture is in scope.
