23. Orchestration pattern

Four patterns are viable. The choice is driven almost entirely by the latency budget, because a voice interface has no loading spinner.

23.1 The distribution argument

Hotel voice traffic is extraordinarily head-heavy. Across deployed in-room assistants the top ~20 utterance families — lights, temperature, DND, curtains, TV, checkout time, Wi-Fi password, housekeeping, towels, wake-up call — account for the majority of all traffic, and they are phrased in a narrow range of ways. Paying full agentic reasoning for “turn off the lights” is spending 800 ms and a Gemini call to answer a question a 50-line matcher answers in 4 ms with higher reliability.

The counter-argument — that a fast path is technical debt that will rot — is real, and it is why the fast path in this design is generated and validated by the eval harness rather than hand-maintained (§24.3). If a fast-path rule ever disagrees with what the agent would have done, that is a test failure, and the rule is removed.

Decision D7 — Three-lane router

Every turn is classified into exactly one of three lanes by a deterministic classifier that costs no LLM call:

  • Fast lane — high-confidence match against a curated grammar of top intents, with all slots filled and no ambiguity. Executes directly through the PDP. Target: 55–65% of turns, p50 under 600 ms.
  • Agentic lane — everything else. Full Gemini reasoning over the capability tool surface. Target: 30–40% of turns.
  • Clarify lane — ASR confidence below threshold, or a known-ambiguous reference with no session context to resolve it. Emits a targeted clarifying question without an LLM call where possible. Target: <8% of turns.

24.1 Fast lane escalation

The fast lane must be able to admit defeat. If the matched action's PDP verdict is anything other than ALLOW, or the tool execution returns an error, or the resolved entity is ambiguous, the turn escalates to the agentic lane rather than failing. The guest never learns which lane served them; they only notice that some answers arrive faster.

24.2 What the fast lane may never do

  • Anything at risk tier T3 or above (§44). Money and irreversible actions always get full reasoning plus explicit confirmation.
  • Anything requiring a state read to decide the target value (“a bit warmer”) — unless the state is already in the pre-fetched snapshot and the delta rule is unambiguous.
  • Anything with a free-text field. Free text means judgement; judgement means the agent.
  • Anything when the session has a pending clarification.

24.3 Keeping the fast lane honest

Five percent of fast-lane turns are asynchronously replayed through the agentic lane. Where the agent would have chosen a different action, the disagreement is recorded. A rule whose disagreement rate exceeds 2% is automatically flagged and, if not fixed within a release cycle, disabled. This turns the fast path from accumulating debt into a continuously validated cache of the agent's own behaviour — which is exactly what it should be.

Decision D8 — Model policy

Gemini 2.5 Flash is the default, with the thinking budget explicitly capped — extended reasoning is a latency disaster on a voice path and rarely improves a request as simple as “dim the lights”. Model IDs are configuration, not code, resolvable per property and per lane, so a model upgrade is a staged rollout rather than a deploy.

Keep one non-Google fallback wired but dormant. Not because Gemini is unreliable, but because a single-provider dependency on the reasoning core of a product installed in guest rooms is a commercial risk a hotel chain's procurement team will raise. The LlmProvider interface plus a smoke-tested alternate path is cheap insurance; you do not need to run it.

Context caching: the system prompt, tool schemas and property-invariant context are stable across turns and across guests in the same property. Cache them. At scale this is a large fraction of input tokens and it also cuts time-to-first-token.

26. Prompt architecture and context assembly

The prompt is a versioned build artefact, assembled from layers with different lifetimes and different trust levels. Treating it as a string in the codebase is how agent systems become unshippable.

│ Who the assistant is, tone, hard behavioural rules, refusal policy, escalation policy,               │

└──────────────────────────────────────────────────────────────────────────────────────────────────────┘

26.1 Rules for context assembly

  • Layers 0–2 are cacheable and must be byte-stable across turns. Any per-turn variation in them destroys the cache hit and costs both money and time-to-first-token. Do not put a timestamp in Layer 0.
  • Layer 3 is where the pre-fetched state lands. Its assembly must be non-blocking — if the state read has not returned within its budget, the layer is assembled without it and the model is told state is unavailable rather than the turn being delayed.
  • Layer 5 is never concatenated into Layers 0–4. The separation is structural, and it is the primary defence against prompt injection.
  • Nothing in any layer is a security control. If a rule in Layer 0 matters, there is a corresponding enforcement in the PDP. The prompt exists to make the model behave well, not to make it safe.

27.2 Why pre-fetch matters more than it looks

In a naive implementation, “make it warmer” costs: LLM call (→ proposes get_state), tool round-trip, second LLM call (→ proposes set_temperature), tool round-trip. That is two LLM calls and two tool round-trips — roughly 1.6 s of avoidable serial latency and double the token cost. With the state snapshot already in Layer 3, it is one LLM call and one tool round-trip. Across the fleet this is the difference between a viable and an unviable unit cost, and it is why §27 step 1 begins before the guest has finished speaking.

28.1 Anaphora and disambiguation

“Turn it off”, “make it cooler”, “the other one”, “same as yesterday” — these are the utterances V1 could not handle, and getting them right is most of the perceived intelligence gain of V2.

  • Last-referenced entity is tracked explicitly in the conversation layer (entity type, ID, label, turn index) rather than left for the model to infer from history. Explicit beats implicit for anything that determines which physical device gets actuated.
  • Resolution order: (1) explicit reference in the utterance; (2) last-referenced entity if within 2 turns; (3) if exactly one device of the plausible type exists in the room, use it; (4) otherwise ask.
  • Never guess between two physical devices. A wrong guess on “turn off the light” in a suite with five zones is a bad experience; a wrong guess that turns off a light the guest was reading by is worse than asking. The clarify lane exists for this.
  • Relative changes require state. “Warmer” with no known current setpoint is a clarification, not a guess. The pre-fetched snapshot means this is almost always available.

29. Deterministic degraded mode

Gemini will be unavailable, rate-limited or slow at some point. What happens then is a product decision, and the default — an error message — is the wrong one.

 LEVEL 0 · NORMAL          Fast lane + agentic lane + clarify lane. Full capability.

 LEVEL 1 · LLM SLOW        Trigger: p95 LLM latency > 2.5s over a 60s window.
                           Action: cap thinking budget to zero, drop to Flash-Lite for slot filling,
                           widen fast-lane matching thresholds, always emit the filled pause.
                           Guest impact: none noticeable.

 LEVEL 2 · LLM DEGRADED    Trigger: LLM error rate > 10%, or p95 > 4s.
                           Action: fast lane only. Anything that does not match the grammar gets:
                           "I can help with lights, temperature, do-not-disturb and service requests
                            right now. For anything else let me connect you to the front desk."
                           Escalation path to staff stays fully open. Guest impact: reduced scope,
                           still useful. THIS IS THE MOST IMPORTANT LEVEL TO GET RIGHT — it is the
                           difference between a degraded product and a broken one.

 LEVEL 3 · ASR DOWN        Trigger: both ASR vendors failing.
                           Action: on-screen touch UI on the device takes over — the screen becomes
                           the interface. Voice announces the switch once. All automation and service
                           requests remain available by touch.

 LEVEL 4 · WAN DOWN        Trigger: device cannot reach cloud.
                           Action: on-device grammar (~25 phrases) → LAN → Edge Gateway → BMS.
                           Lights, climate, DND, curtains, TV still work. Service requests are queued
                           locally and flushed on reconnect, and the guest is TOLD they are queued.
                           Screen shows an offline indicator.

 LEVEL 5 · EDGE DOWN       Trigger: Edge Gateway unreachable and cloud unreachable.
                           Action: device announces the failure plainly and points to the room phone.
                           A honest "I can't reach the room systems right now, please use the phone"
                           beats silence or a lie. Health alert fires to ops.
The degraded-mode principle

At every level the assistant says what it can still do, rather than what it cannot. “I can help with lights, temperature and do-not-disturb right now” keeps the guest using the product; “Sorry, I'm having trouble” teaches them to stop trying. The set of capabilities available at each level is configuration, so it can be tuned per property without a release.
