Part IFoundations

1. Who owns what

The split is deliberate: you own sound, we own meaning. Nothing about understanding, deciding or authorising lives on the device, and nothing about microphones or speakers lives in the cloud.

Wake word detection—Privacy. No audio may leave the room before the wake phrase fires.
Echo cancellation, beamforming—Needs the raw mic array; must run before the signal leaves the mic path or barge-in is impossible.
Voice activity detection, endpointing—Signalling end-of-turn locally saves 200–400 ms versus a cloud silence timer.
Speech-to-text (today)Speech-to-text (phase 2)See §16.

One rule that explains many others

The device never sends a room number, and never receives one it can act on. Identity is established once, at connection time, and the service derives tenant, property and room from it. If you ever find yourself wanting to put a room in a message, something has gone wrong — and there is nowhere in the protocol to put it.

There is no request ID, and you don't need one

The connection is per-device and turns are serialised — one turn in, one ack plus one speak out. The turnId on the response is what you log against. Do not send a second turn before the first has produced speak; queue it or drop it.

Part IIThe client

4. Complete WoohooClient

Production-shaped, using OkHttp, which is already in your build.gradle. No new dependency.

package com.sb.woohoo.net

import android.os.Handler
import android.os.Looper
import okhttp3.*
import org.json.JSONObject
import java.util.concurrent.TimeUnit
import java.util.concurrent.atomic.AtomicBoolean

/**
 * Single long-lived connection to the Woohoo service.
 *
 * Lifecycle: connect() once when the app starts, disconnect() when it stops.
 * NOT one connection per utterance — see §5.
 */
class WoohooClient(
    private val deviceId: String,
    private val endpoint: String,
    private val firmware: String,
    private val listener: Listener,
) {
    interface Listener {
        /** Identity accepted. Safe to accept utterances from here. */
        fun onReady(property: String, room: String, assistantName: String, phrasePackVersion: String)
        /** Play from the local phrase pack IMMEDIATELY. Do not wait for onSpeak. */
        fun onAck(filledPause: String)
        /** The real answer. Synthesise and play. */
        fun onSpeak(text: String, turnId: String)
        fun onScreen(text: String)
        fun onError(code: String, detail: String, fatal: Boolean)
        fun onConnectionStateChanged(state: State)
    }

    enum class State { DISCONNECTED, CONNECTING, READY }

    private val http = OkHttpClient.Builder()
        // Hotel Wi-Fi drops connections without a close frame. Keepalives detect it.
        .pingInterval(20, TimeUnit.SECONDS)
        .connectTimeout(10, TimeUnit.SECONDS)
        .readTimeout(0, TimeUnit.SECONDS)   // 0 = never; the socket is long-lived
        .retryOnConnectionFailure(true)
        .build()

    private var ws: WebSocket? = null
    private var retries = 0
    private val shuttingDown = AtomicBoolean(false)
    private val main = Handler(Looper.getMainLooper())

    var state: State = State.DISCONNECTED
        private set(value) {
            field = value
            main.post { listener.onConnectionStateChanged(value) }
        }

    val isReady: Boolean get() = state == State.READY

    // ─────────────────────────────────────────────────────── lifecycle

    fun connect() {
        if (shuttingDown.get() || state != State.DISCONNECTED) return
        state = State.CONNECTING

        val request = Request.Builder().url(endpoint).build()
        ws = http.newWebSocket(request, object : WebSocketListener() {

            override fun onOpen(webSocket: WebSocket, response: Response) {
                // hello MUST be first. Everything else is rejected until identity exists.
                webSocket.send(
                    JSONObject()
                        .put("type", "hello")
                        .put("deviceId", deviceId)
                        .put("firmware", firmware)
                        .toString()
                )
            }

            override fun onMessage(webSocket: WebSocket, text: String) {
                handle(text)
            }

            override fun onFailure(webSocket: WebSocket, t: Throwable, response: Response?) {
                state = State.DISCONNECTED
                scheduleReconnect()
            }

            override fun onClosed(webSocket: WebSocket, code: Int, reason: String) {
                state = State.DISCONNECTED
                if (!shuttingDown.get()) scheduleReconnect()
            }
        })
    }

    fun disconnect() {
        shuttingDown.set(true)
        ws?.close(1000, "client shutdown")
        ws = null
        state = State.DISCONNECTED
    }

    // ─────────────────────────────────────────────────────── sending

    /**
     * Send one transcribed utterance.
     *
     * @param asrConfidence the REAL score from the recogniser. Below 0.60 the service asks
     *        the guest to repeat rather than guessing at a physical action; a hardcoded
     *        constant makes it guess when it shouldn't.
     * @return false if not connected — show the offline affordance (§17).
     */
    fun sendTurn(transcript: String, asrConfidence: Double): Boolean {
        if (!isReady) return false
        if (transcript.isBlank()) return false
        return ws?.send(
            JSONObject()
                .put("type", "turn")
                .put("transcript", transcript.take(2000))
                .put("asrConfidence", asrConfidence.coerceIn(0.0, 1.0))
                .toString()
        ) ?: false
    }

    fun sendBargeIn() {
        ws?.send(JSONObject().put("type", "barge_in").toString())
    }

    fun sendHealth(rssi: Int, wakeFalseAccepts: Int) {
        ws?.send(
            JSONObject()
                .put("type", "health")
                .put("rssi", rssi)
                .put("wakeFalseAccepts", wakeFalseAccepts)
                .toString()
        )
    }

    // ─────────────────────────────────────────────────────── receiving

    private fun handle(text: String) {
        val msg = try { JSONObject(text) } catch (e: Exception) { return }
        main.post {
            when (msg.optString("type")) {
                "ready" -> {
                    retries = 0
                    state = State.READY
                    listener.onReady(
                        msg.optString("property"),
                        msg.optString("room"),
                        msg.optString("assistantName", "Voice Genie"),
                        msg.optString("phrasePackVersion"),
                    )
                }
                "ack"    -> listener.onAck(msg.optString("filledPause"))
                "speak"  -> listener.onSpeak(msg.optString("text"), msg.optString("turnId"))
                "screen" -> listener.onScreen(msg.optString("text"))
                "error"  -> {
                    val code = msg.optString("code")
                    // UNKNOWN_DEVICE means the socket is closed and retrying is pointless —
                    // this is a provisioning problem, not a network one.
                    listener.onError(code, msg.optString("detail"), fatal = code == "UNKNOWN_DEVICE")
                    if (code == "UNKNOWN_DEVICE") shuttingDown.set(true)
                }
            }
        }
    }

    // ─────────────────────────────────────────────────────── reconnection

    /**
     * Exponential backoff with FULL jitter, capped at 60s.
     *
     * The jitter is not optional. Without it, a property-wide Wi-Fi blip makes 300 devices
     * reconnect in lockstep and you have caused your own outage. Random across the whole
     * window, not "base + random" — that still clusters.
     */
    private fun scheduleReconnect() {
        if (shuttingDown.get()) return
        val capMs = minOf(1000L shl minOf(retries, 6), 60_000L)
        retries++
        val delay = (Math.random() * capMs).toLong().coerceAtLeast(250L)
        main.postDelayed({ connect() }, delay)
    }
}

5. Connection lifecycle

  app start ──► connect() ──► onOpen ──► send hello ──► ready ──► State.READY
                    ▲                                                │
                    │                                                │ utterances flow
                    │                                                │ here, many of them,
                    │                                                │ on the SAME socket
                    │                                                ▼
                    └──── scheduleReconnect() ◄──── onFailure / onClosed
                          (jittered backoff)

  app stop ──► disconnect()      shuttingDown = true, no reconnect

Bind it to the process, not to an activity or a turn. On a dedicated in-room device the natural home is a foreground service that lives as long as the app.

class VoiceService : Service(), WoohooClient.Listener {
    private lateinit var client: WoohooClient

    override fun onCreate() {
        super.onCreate()
        client = WoohooClient(
            deviceId = DeviceIdentity.current(this),
            endpoint = BuildConfig.WOOHOO_WS_URL,
            firmware = BuildConfig.VERSION_NAME,
            listener = this,
        )
        client.connect()   // once. not per turn.
    }

    override fun onDestroy() {
        client.disconnect()
        super.onDestroy()
    }
}
Why one connection matters, with the arithmetic

Before a single byte moves, opening a connection costs three network round trips: TCP handshake, TLS handshake, WebSocket upgrade. On hotel Wi-Fi a round trip is typically 40–100 ms, so that is 120–300 ms of pure overhead — paid on every utterance, forever, buying nothing.

Against a p50 budget of about 1,100 ms wake-to-response, that is a quarter of your budget spent dialling. Open it once.

6. Reconnection and jitter

SituationBehaviour
Socket dropsReconnect with jittered backoff, 250 ms → 60 s cap. Re-send hello.
Reconnect within 30 minConversation context survives server-side, keyed on the room. A brief drop mid-conversation loses nothing.
Reconnect after a pending confirmationThe frozen action expires after 90 s regardless. If the guest says "yes" later, they are told it expired and nothing is charged.
UNKNOWN_DEVICEStop. This is provisioning, not networking. Retrying forever hides the real fault. Show a service state on screen.
Offline for a long periodEnter offline mode (§17). Keep trying in the background at the 60 s cap.

7. Error handling

codeMeaningDo
NOT_AUTHENTICATEDA frame arrived before helloClient bug. Send hello, retry once.
UNKNOWN_DEVICEUnknown, revoked, or room binding brokenFatal. Socket closes. Stop retrying; show a service message.
RATE_LIMITED>30 turns from this device in an hourSay something apologetic; back off a few minutes.
BAD_FRAMENot valid JSONClient bug. Log it.
TURN_FAILEDThe turn threw server-sideSay something honest and offer the front desk. Do not auto-retry — it may have half-executed.
Never invent an outcome

On any error, do not say "Done". The single most damaging failure mode in this product is the confident false confirmation: the guest hears "I've turned off the lights", the lights stay on, and the device is dead to them. If you don't have a speak, say you couldn't do it.
